## 一句话

八月 = **「壳牌 RPA 打通交付月 + 转进系统重构」**。shell_convert / SDCC 从卡壳到全流程打通、初步交付上线，月底又主动转向“清理死代码 + 统一命名”的系统性重构；案件管理系统也在月中干净地推到了生产环境。职业定位这条线也跪实了一步——认清自己是“AI 应用工程师型”，下一站真目标是物流/供应链数字化。

## ✅ 干了啥

- **壳牌 SDCC RPA(主线)**：shell_convert 转换逻辑改完 → `uploader.py` 全流程测试成功(本月最大突破) → session 复用打通 → 梳理清完整数据流 → 8/21 初步交付上线 ✅ → 月底启动系统性重构(方向一：清理死代码 + 统一命名)，并决定 RPA 与 API 两条上传路径先并存。
- **案件管理系统配置**：从 IT 培训、3.1 新建模版 → 3.3 节点模板权限 → **生产环境配置完成** ✅。

- 顺手：整整一周入职培训(Git 、DDD)，线上培训。

## 🧠 收获 & 想明白的

- **架构讨论才是真难点**：AI 从 0 到 1 能帮忙搭架构，但到了半成品改需求/加功能，真正考验的是自己懂不懂架构编排、文件职责与耦合关系。
- **改动粒度要小**：一次性重写 8 个文件推 GitHub，大文件超 token 失败——大改动应该拆成小提交。
- **先梳理/画图再动手**值得固定成习惯：用 XMind 梳清架构、想清数据流之后再重构，效率明显高一截。
- **工程硬知识**：Inno Setup 打包、onedir/onefile 区别、沙盒概念、uv、Git 完整工作流(diff/commit/push/PR、强制 reset)、DDD、`git apply`、贫血模型 vs 富模型的取舍。
- **职业定位跪实了**：“AI 应用工程师型”画像，下一站瞌准物流/供应链数字化 + AI 应用的交叉带。
- **一个信号**：事务性工作(商道积分导数据、案件管理系统配置)稳定占用时间，会挤压主线深度推进的空间。

## 🧭 复盘启发

- Token / 协作效率是全月反复出现的瓶颈——从 8 个文件超 token 失败，到月底还在找更省 token 的协作方式。建议把“改动粒度控制 + 分批协作”固化成默认工作方式，而不是每次卡住才临时想办法。
- 这个月壳牌 RPA 走完了一个完整的“卡壳→打通→交付→重构”周期，这个节奏值得沉淀成方法论：先想清数据流 → 小范围验证 → 再谈重构收尾，下次接新项目可以直接套用。
- 职业定位和实际工作内容已经开始对齐，可以更有意识地把每个项目当成“能证明自己”的案例来经营——尤其是壳牌这条主线，交付 + 重构都是具体可讲的故事。
